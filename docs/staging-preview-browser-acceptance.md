# Real gateway browser acceptance

This optional local test connects a real browser to the Python preview gateway.
It does not use Playwright route fulfillment for Hub or preview requests, and
does not start a worker, Docker job, NAS connection or public route.

From `hub-ui`, with the existing npm dependencies and browser installed:

```text
node node_modules/@playwright/test/cli.js test --config playwright.preview-live.config.ts --max-failures=1
```

The separate config/test directory leaves ordinary UI E2E and hosted CI unchanged.
The current harness uses the existing `desktop-linux` Docker context and cached
immutable validation image
`sha256:6642cd751e2814d21e367fda47c47e67c584ffe7fe62270427441359fd69efb2`.
It never pulls or installs dependencies. Windows uses the existing Edge channel;
other platforms need Playwright Chromium already available.

The owned disposable container has a read-only source bind and root filesystem,
dropped capabilities, one CPU, 512 MiB RAM/no additional swap, 128 PIDs and a
128 MiB private tmpfs. Only two ephemeral loopback host ports are published.
`localhost` is the test Hub origin and `127.0.0.1` is the preview origin, so host
cookies cannot cross merely because both origins use different local ports.
Both serve actual HTTPS using a one-hour synthetic certificate generated inside
tmpfs. Browser certificate checking is disabled only for this self-signed fixture;
this test does not verify production TLS trust or Cloudflare Access.

The Python fixture creates disposable SQLite repositories and a real
`SessionStore`, `require_human`, `attach_staging_routes`, `StagingResourceStore`
and `PreviewBroker`. Test-only login/control endpoints create and revoke the
synthetic human session and advance the fixture clock. They are not production
routes. An immutable byte mapping implements the fixed artifact reader, without
worker HTTP or Docker execution. The HTTPS transport adapter and minimal parent
page are test infrastructure, not a replacement Hub frontend. The minimal parent
iframe has `sandbox="allow-scripts"` and `referrerpolicy="no-referrer"`; it does
not reproduce the React dashboard's `credentialless` or `allow` attributes.
Absence of preview cookies here proves hostname separation, not those dashboard
attributes.

Seven tests cover:

- Real static and dynamic ES-module imports, CSS, JSON and decoded TrueType font
  through capability URLs. `document.fonts.load` must return the loaded face and
  `document.fonts.check` must pass inside the opaque frame.
- Both 390 × 844 phone and 1440 × 1100 desktop viewports, opaque frame origin, blocked parent and cookie reads,
  and absence of cookies, authorization and referrer headers at the preview server.
- Browser CSP denial of a sibling capability, resource-specific file binding and
  anonymous capability-issuance denial.
- A valid authenticated session receives 403 when capability issuance lacks CSRF,
  supplies the wrong CSRF value or supplies a foreign Origin with valid CSRF.
  Successful issuance before and after establishes that the session remains valid.
- Immediate denial of retained capability requests after actual session logout,
  project-grant revocation and capability expiry; navigating the frame again also
  fails to load the application.

Run on 24 October 2026: **7 passed**, using real Edge and the pinned Python image.
The owned servers shut down and the exact container is removed in `afterAll`,
including test failures; the test verifies container absence. A UUID ownership
label and exact container ID guard cleanup, including ambiguous create failures;
foreign collisions are refused. A cleanup error cannot replace an earlier test
failure. No capability URLs
or cookies are intentionally logged. Traces, video and screenshots are disabled.
The server retains only fixed asset-name observations and header-presence flags.

The tiny original font has an empty `.notdef` and one triangle for U+0041. It was
generated by `tests/fixtures/generate_staging_preview_font.py` using only Python's
standard library; no system or third-party font was copied. The resulting base64
bytes are embedded in the server fixture, so browser acceptance has no font-tool
dependency. `tests/test_staging_preview_font_fixture.py` checks exact regeneration
and the TrueType whole-file checksum.

Limits: this does not exercise the React resource controls,
source submission/build execution, worker TLS, rootless kernel enforcement,
canonical held-work admission, actual phone hardware, public hostname routing or
production identity-provider login. Existing separate tests cover some of these
boundaries. A live phone-access claim still requires the approved separate preview
hostname and installed deployment acceptance.
