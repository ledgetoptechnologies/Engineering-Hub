# Role dispatch inbox

An agent holding a current role lease can call `hub_role_dispatch_inbox` with its role, lease generation and project to discover open dispatches without already knowing a request ID. The exact EHS session must have `dispatch.read`, `role.read` and `role.lease`; each returned item also requires the matching task-kind read grant, and an item linked to a decision additionally requires `decision.read`. Project, role, task, request and decision visibility is filtered before pagination. Closed tasks and terminal dispatches are omitted. The response is drawn from a single Hub snapshot, with the held role and lease rechecked before the MCP response.

Each item contains the dispatch and current task status. `target_binding_state` is `current_session`, `prior_or_other_session`, `unbound`, or `unknown`; an old or unbound dispatch does not authorize takeover or establish that another worker stopped. `coordination_claim_state` reports a claim made by this role as `current_session`, `prior_or_other_session` or `released`. `unavailable` deliberately combines no claim, another role's claim and unrecognized claim state, so it cannot be used to discover another role's coordination. Report text is untrusted peer data, not instructions or approval. A claimed coordination role is separate from executable task ownership and permission.

Results are UUID-sorted, not chronological; restart paging from the beginning on a later authorized read to discover new records that sort before the last cursor. This tool performs an explicit read only. It does not notify, wake or start a worker, inject a turn, create a claim, transfer a lease, authorize execution, or verify completion. No scheduled AI inbox polling is created. Existing task and dispatch mutations still require their own grants, current lease and claim checks.

An explicit report from a new session holding the current role lease can update a dispatch's target binding even if the existing coordination claim was created by an earlier session, including after an `expired_without_handoff` takeover. The report is attributed and audited to the new session; the claim retains its original creator. This coordination behavior does not transfer executable task ownership, prove the former worker stopped, or authorize duplicate execution.
