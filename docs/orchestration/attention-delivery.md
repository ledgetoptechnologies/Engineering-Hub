# Addressed attention hints

A Hub owner may explicitly configure an expiring route for one active project to the exact currently held orchestrator role generation, EHS installation, session and Hub-grant revision. Route creation and revocation require the authenticated owner and CSRF protection. A route is off when absent, and becomes unusable after its expiry, owner epoch or boot change, session or grant revocation, grant revision change, role transfer, or loss of the relevant project/role permissions. A changed route invalidates old stream subscriptions; the client must subscribe again.

The route owner can view or change `/api/hub/v1/projects/{project}/attention-route`, and can read bounded `/api/hub/v1/projects/{project}/attention-receipts` history. Receipt IDs are UUID-sorted rather than chronological, so restart paging from the beginning to find newly inserted receipts. A session with a matching current route can use the MCP tools `hub_addressed_attention_list` and `hub_addressed_attention_ack`. The list independently enforces task-kind read grants, current role and project access; the stream does not grant access. Acknowledgment produces one deterministic receipt for a given intent revision and exact recipient session/role generation. Retrying while the route and intent remain valid returns the same receipt, including after route renewal for the same session and generation. If the task closes, the intent is superseded, or authorization changes, a retry fails closed; the owner can inspect retained receipt history. An acknowledgment records an agent assertion only: it does not verify work, task completion, actual wake, or user approval.

A connected authorized client may open `GET /api/agent-sessions/v1/hub-attention-stream?project=...&generation=...` on its configured EHS private transport origin, using its EHS bearer credential in the Authorization header. Never put that credential in a URL or logs. This is a server-sent event stream. After registration it emits a content-free `attention-ready` event, meaning only that the client should perform a scoped catch-up read. After a committed manual or automatic stale transition, the server may emit `attention-check` to the matching subscribed session only if the session currently has visible pending attention. Both events contain `{}` and no task, project, intent, or message text. Read the MCP list after a hint; acknowledge only when the agent actually accepts the attention. Register-before-catch-up and durable pending intents permit recovery after a missed hint or reconnect; hints are coalesced, bounded, and are not delivery receipts.

Session revocation and explicit route changes signal closure. Quiet streams use a deadline timer; suspend, a stalled transport or process scheduling can delay closure, and validity is checked before every later hint. Other grant, role or pause changes are rechecked before any later hint, but do not necessarily close a quiet stream immediately. A content-free hint can race a revocation after the final check and before a network write; do not treat network acceptance as proof the client received it. A connected, correctly configured agent client must actively subscribe, read and acknowledge. This interface does not itself start or wake an idle agent, and no real agent delivery or reboot/idle wake is established by the synthetic loopback tests. There is no scheduled AI inbox polling, generic outbox publication, execution authorization or automatic replay.

The existing downloaded agent-session helper offers an explicit foreground `listen-attention` command with `--profile-dir`, `--session`, `--project` and `--generation`; use `--private-vpn` only for a profile enrolled in that mode. It reads the protected session profile, refuses redirects and proxies, and prints only fixed content-free event names. It neither starts automatically nor reconnects, reads the MCP list, acknowledges an intent, injects an agent turn, or proves wake. The user or an authorized host integration owns the process and its shutdown.
