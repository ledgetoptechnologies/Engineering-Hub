# Foreground attention context adapter

The optional `python -m engineering_hub.attention_client` is an explicitly invoked, foreground adapter for an already configured exact EHS session and owner-approved attention route. It does not start an agent, inject a turn, run a model, install a service, change client configuration, reconnect automatically, poll on a timer, or acknowledge an item merely because a hint arrived.

Supply `--profile-dir`, `--session`, `--project` and `--generation` before the subcommand. A profile enrolled for the private VPN additionally requires `--private-vpn`. The adapter reads the existing protected session profile, uses the same EHS credential for the event stream and MCP, rejects redirects and environment proxies, and checks `session_identity` against the profile before reads and acknowledgments. The server still authorizes every operation. Do not place bearer credentials in command arguments, URLs, logs, or copied transcripts.

* `listen` subscribes before its catch-up read and reads only when the stream emits `attention-ready` or `attention-check`. The process exits on stream loss, session expiry, protocol error, or cancellation; the owner decides whether to restart it.
* `read` performs one explicit catch-up. `read --after UUID` continues a prior truncated page, without silently creating a scheduled poll.
* For the default orchestrator role, `ack --intent-id UUID --revision N` is a separate explicit acknowledgment after the host or agent has actually accepted the reference. Acknowledgment is an assertion by that EHS session, not proof of task completion, work execution, human approval or an agent wake. A retry after task/intent/route authorization changes can fail closed; the owner can inspect retained receipts.

Output is newline-delimited JSON. Reference records contain only validated project, role generation, intent and dispatch identifiers and intent revision, with `trust: untrusted_hub_data`, `execution_authorization: false` and `wake_verified: false`. Peer-authored text is not copied into the output and must never be interpreted as an instruction or authorization. Treat stdout as project-private data and do not attach it to a different agent session. This is an exportable reference for an already active and separately authorized host, not automatic turn context injection.

Each catch-up reads at most ten pages of 50 entries. A final `attention_catchup` record has `complete: false` and `next_after` when more pages remain; use the explicit `read --after` continuation. UUID cursors are not chronological: restart from the beginning on each new hint or reconnect to find later insertions below a prior cursor. References are deduplicated within one catch-up and can repeat on later hints; a changed revision is never suppressed. No notification or stdout write proves that the host consumed an item. Keep the original pending record until the host explicitly acknowledges it.

The synthetic tests use a real loopback SSE/MCP connection but do not run an agent model or change a live installation. Existing Codex and Hermes client configurations remain separate; no exact-session agent turn delivery, idle wake, restart recovery, or production deployment is claimed.

For worker dispatches, pass `--role backend` (or the exact configured worker role) before the subcommand. `listen` and `read` then retrieve only dispatches bound to that session and role, and emit `worker_dispatch_reference` records containing project, role, task and dispatch identifiers and dispatch revision. The server independently validates all grants and the exact route. A wrong-scope or malformed worker reference stops the adapter rather than producing a misleading completed catch-up. After the host explicitly accepts a reference, invoke `ack --dispatch-id UUID --revision N` separately with the same role and profile. Using an orchestrator intent ID for a worker route, or a dispatch ID for the orchestrator route, is rejected. The worker receipt records the session's assertion; it does not prove wake, execution, task completion or takeover. Prior or unbound dispatches remain available through `hub_role_dispatch_inbox`, not this notification stream.

For an answered-decision worker reference, the adapter emits `event_type: decision_answered` with a decision ID and revision, never the answer text. After explicit acceptance, add `--decision-id UUID --decision-revision N` to the worker `ack --dispatch-id ... --revision ...` command. Inspect the answer separately using the scoped `hub_dispatch_decisions` tool; the adapter does not automatically acknowledge or resume it.

To inspect an answered-decision reference, explicitly run `inspect-answer --dispatch-id UUID --revision N --decision-id UUID --decision-revision N` with the same worker `--role`, project, generation and protected profile. The server rechecks the exact owner-admitted route, current role/session binding, active task, task read and decision read grants, and both revisions. Inspection is available before or after acknowledgment while the dispatch is still waiting on that decision. Output contains the answer as project-private `untrusted_hub_data`; it is not an instruction or execution authorization. Inspecting neither acknowledges nor resumes. If the route, task, role, dispatch or decision changes, inspection fails closed; use the authorized current workflow to obtain a fresh reference.

For a `worker_report` attention reference, the orchestrator adapter also emits its report ID, revision and kind without report text. Explicitly run `inspect-report --intent-id UUID --revision N --report-id UUID --report-revision N` with the same orchestrator profile, project and generation. The returned note is project-private untrusted worker data, never proof of completion or an instruction. The scoped read revalidates the current route and role session, underlying task and decision grants, and immutable report linkage before response. It is available before acknowledgment and after acknowledgment by that same still-authorized session and generation; changed or closed work fails closed. Inspection does not acknowledge, execute or verify work.
